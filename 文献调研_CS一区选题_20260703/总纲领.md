# 总纲领：单细胞算法 GPU 迁移 Benchmark + Agent（承上启下）

配套：`选题思路.md`（战略）、`深化报告_五问与框架.md`（五问）、`文献汇总.csv`（56 篇）。

## 一句话定位

```
承上(第一篇 CS 一区论文): 
  "单细胞算法 CPU→GPU 迁移的 Benchmark 与领域正确性协议"
  —— 方法动物园 + 统计等价正确性判据 + 精度-速度-显存 Pareto + scMAE 旗舰迁移案例
     (+ 可选: API-模型多agent 自动迁移 baseline)
启下(毕业论文):
  "面向单细胞算法的 GPU 迁移专用 Agent"
  —— 在上面的 benchmark 上, 微调/RL 出领域特化的迁移 agent, 领域正确性做奖励
```

第一篇的智力脊梁 = **为随机领域算法定义并验证"迁移正确性"（统计等价）**。这是 KernelBench/
ParEval/Kevin 都没有的、领域特有的、更难的判据（见深化报告 Q2）。

## 工作量分解（第一篇，强度A为主，B为加分）

| 模块 | 内容 | 估时 | 风险 |
|---|---|---|---|
| M1 缺口实测 | 3-5 方法 CPU vs GPU wall-time/占用/显存，量化"缝" | 1 周 | 低 |
| M2 正确性协议 | 定义+实现 统计等价判据(确定性容差 + 随机TOST等价band) | 2-3 周 | 中(智力核心) |
| M3 方法动物园 GPU 重实现 | scMAE旗舰 + 8-12 方法的 GPU-native 版(cupy/cuML/torch) | 4-6 周 | 中高(工程量) |
| M4 数据集协议 | 动物+植物+大规模(百万级)，统一预处理 | 1 周 | 低 |
| M5 三轴评测 harness | 正确性×加速比×显存, 可扩展性曲线, Pareto | 2 周 | 低 |
| M6 诊断分析章 | 复用已有洞察(重构≠聚类/伪结构有害/head非瓶颈/DEC机制) | 1 周 | 低(现成) |
| M7(可选,强度B) | API-模型多agent 迁移 baseline + 正确性gate 闭环 | 3-4 周 | 中高 |

关键路径 = M2(正确性协议) → M3(GPU重实现) → M5(评测)。M2 是新意所在，先攻。

## 数据集协议（必须有"规模"轴，否则 GPU 加速故事不成立）

- **小/中(已有)**：Macosko 44k / Quake / Melanoma / 植物 SRP182008 13k / CRA002977 11k。
- **大规模(需补)**：≥数十万~百万细胞（如 Tabula Sapiens / 拼接多个图谱）。这是**证明 GPU
  价值的关键**——小数据上深度方法 GPU 利用率低(我们实测1-8%)，加速故事要靠规模撑。
- 每个数据集：CPU 参考实现 + GPU 迁移版，同随机源，跑正确性+计时。

## 成果如何衡量（三轴 + 两条曲线）

```
正确性  : 确定性子步 allclose(rtol); 端到端 ARI/NMI 落在 CPU 跨种子噪声band内(TOST等价)
加速比  : wall-time speedup (端到端 & 分阶段), throughput (cells/s)
显存    : 峰值显存, 是否 OOM
可扩展性: speedup vs 细胞数 曲线 (10k→100k→1M)
权衡    : accuracy-speed Pareto 前沿 (哪些方法迁移后既快又不掉点)
迁移成功率(若做agent): 自动迁移通过正确性gate 的比例
```
一句话成果 = "在保证下游聚类/降维指标统计不退化的前提下，把 N 个单细胞算法迁移到 GPU，
给出可扩展到百万细胞的 X× 加速与显存全景；并（可选）证明一个 LLM-agent 能自动完成迁移。"

## Agent 到底必不必要？（回答你的原问）

**第一篇：不必要（强度A）。** 手工/半自动 GPU 重实现 + 正确性协议 + benchmark 已足够成一篇
（NeurIPS D&B / ICML benchmark 认这种）。agent 作为 future work 一节即可。
**若要上限更高：加强度B 的 API-agent baseline。** 但 agent 的"完全体"（自训/RL 专用模型）
**留给毕业论文**才是最优分配——那时 benchmark 已托底，agent 才是主角、才有训练数据与评测台。

## 分阶段执行（每阶段可独立交付、风险递增）

```
Phase 1 (立即, 1周): M1 缺口实测。产出"CPU↔GPU gap 报告"，坐实前提。
        —— 用 scMAE旗舰 + 1图对比 + 1降维, 在 10k/44k/(拼)200k 上测 CPU vs GPU。
Phase 2 (2-3周): M2 正确性协议 + M4 数据集协议。产出"迁移正确性判据"草案+实现。
Phase 3 (4-6周): M3 GPU 重实现动物园 + M5 评测。产出核心结果表/Pareto/可扩展曲线。
Phase 4 (1-2周): M6 诊断分析章 + 论文初稿(强度A)。
Phase 5 (可选,3-4周): M7 API-agent 迁移 baseline(强度B)。
毕业论文: 自训/RL 单细胞迁移专用 agent, 在本 benchmark 上评测。
```

## 立即可做的第一步（Phase 1，不需要你再拍板细节）

**M1 缺口实测**对所有强度/选题都有用，且直接验证整个方向的前提。内容：
1. 选 scMAE(我们的AdaptiveSwitch旗舰) + 一个图/对比方法 + 一个降维方法；
2. 在 10k / 44k / 拼接~200k 细胞上，分别测 CPU-only 与 GPU 的：端到端 wall-time、
   分阶段耗时（预处理/图构建/训练/聚类/评测）、GPU 利用率、峰值显存；
3. 产出 `gap报告`：哪一步是 CPU 瓶颈、GPU 化能省多少、随规模如何变化。

这一步会告诉我们"缝"到底多大、哪些阶段最值得迁移，是 benchmark 设计的事实基础。

# 未来方向（搁置）：单细胞算法迁移到国产昇腾 NPU

状态：**搁置/仅想法**（2026-07-03）。用户目前**没有昇腾卡的连接**，只是一个设想。
先记录，等有卡、且手上这篇论文完成后再评估。**不纳入当前论文范围。**

## 一、先把"新浪潮"讲清楚（用户没看懂的那个词）

我说的"新浪潮"就一件事：**2025-2026 年突然涌现一批"让 AI/LLM 自动写或迁移硬件加速代码"
的研究**。以前写 GPU 内核(CUDA kernel)是专家手工活；现在大家用 LLM agent 自动生成/优化。
分两侧：

- **NVIDIA(CUDA)侧**：KernelBench(评测 LLM 写 GPU 内核的标准)、Kevin-32B(用 RL 训模型写
  CUDA)、CUDA-Agent(大规模 agentic RL)…… → 很挤，重资源团队在卷。
- **昇腾(NPU)侧**：AscendKernelGen(LLM 生成昇腾算子, 编译成功率 0%→95.5%)、AscendCraft
  (DSL 引导的转译)、Episodic-Agent(昇腾算子优化 agent)…… → **刚起步、很空、2026 才冒头**。

你的**毕业论文（自动迁移 Agent）就属于这股浪潮**。区别是：别人做通用算子，你做"单细胞
算法"这个垂直领域——而且如果落在昇腾侧，几乎无人竞争。

## 二、为什么昇腾方向（未来）诱人

1. **几乎无人**：单细胞算法 × 昇腾 = 完全空白（搜遍无人做；"ascend"的搜索命中是个同名
   R 包，无关）。
2. **生态不成熟反而是机会**：昇腾算子优化论文原话"unlike CUDA, the ecosystem offers few
   public kernels to learn from"——缺参考代码、数据稀缺，正是可发论文的地方。
3. **政策/战略相关**：国产算力自主，国内一区尤其买账。
4. **工具已有起点**：torch_npu(Ascend PyTorch 适配)、华为 GPU2Ascend/MindStudio 自动迁移
   工具、CANN(对标 CUDA 的栈)都存在，不是从零。

## 三、你已完成工作在这条路上的承重（与 GPU 路一致）

- 方法动物园 = 被迁移的工作负载。
- 诊断 + 结构感知/稀有细胞正确性判据 = "迁移对了没有"的验收标准（昇腾栈不成熟，
  算子/精度差异更易破坏稀有结构，判据更承重）。
- DEC+std-floor = 旗舰案例（方差地板机制扛得住昇腾算子/精度差异吗？）。

## 四、真实风险（为何现在搁置而非马上做）

- **没有卡的连接**（用户当前无法登录昇腾机器）——硬门槛，无法起步。
- 昇腾生态不成熟：调试难、文档少、坑多，工程代价高。
- 需要先把 CANN + torch_npu 环境跑通（第一道坎）。

## 五、若将来启动，第一步（昇腾版"缺口实测"）

1. 拿到卡的连接 + 型号(910A/910B/310)、装 CANN + torch_npu。
2. 把旗舰 scMAE+DEC+std-floor `.to("npu")` 搬上去：① 能否跑通 ② 稀有亚型有没有算丢
   (用结构感知判据) ③ 比 CPU/H100 快多少 / 能效如何。
3. 记录哪些算子在昇腾上缺失/需自定义——这就是迁移 agent 的工作清单。

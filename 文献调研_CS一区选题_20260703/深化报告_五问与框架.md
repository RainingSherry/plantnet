## Q1. 有没有现成的"算法级 GPU 迁移 benchmark"？我们会不会撞车？

**部分有，但我们的位置仍然空着。**
- **ParEval-Repo**（arXiv 2506.20938, 2025）已做"仓库级 HPC 翻译"——但对象是**HPC 迷你应用**
  （流体求解、物理内核），正确性是数值/编译级。
- **KernelBench**（250 个 PyTorch 算子）、System-Level HPC Optimization benchmark ——都是
  **通用算子/系统级**。
- **没有任何 benchmark 覆盖"领域 ML 算法（单细胞 DR/聚类/上下游）的 CPU→GPU 迁移，且以
  下游生物学指标不退化为正确性判据"。** 这是我们的空地。

**差异化三点（写进 related work 就能挡审稿人"这不就是 KernelBench/ParEval")：**
1. 粒度：**整算法/整管线**，不是单 kernel；
2. 领域：**单细胞方法动物园**，各自 bespoke、CPU-bound，无 GPU-native 版；
3. 正确性：**统计等价（聚类/降维指标落在噪声带内）**，不是 bit-match（见 Q2）。

## Q2. "正确性判据"是必须的吗？—— 不仅必须，它就是这篇论文的脊梁

**是脊梁，不是可选项。** 证据：《The Correctness Illusion in LLM-Generated GPU Kernels》
（2606.20128）刚刚证明 LLM 生成的内核**能过弱测试但其实是错的**；ProofWright 用 agent+
形式化验证 CUDA。说明"正确性"正是这条线当前最痛、最热的点。

而**我们有一个比它们更难、更新的正确性问题**：单细胞算法（KMeans n_init、DEC、Leiden、
UMAP、扩散）**本身是随机的**，CPU 和 GPU 版永远不会 bit-match。所以：
```
迁移正确性 ≠ 数值 bit-match
迁移正确性 = 统计/语义等价：
   - 确定性子步(如距离矩阵/PCA): 数值容差等价 (allclose, rtol)
   - 随机端到端(如聚类): 同随机源下, GPU版与CPU参考的 ARI/NMI 落在
     CPU 自身跨种子噪声带内, 统计不可区分 (如 TOST 等价检验)
```
**"为随机领域算法定义并验证 GPU 迁移正确性"——这件事没人系统做过，是本文的核心智力贡献。**
没有它，快了的 GPU 代码只是"更快地算错"。这一条足够撑 CS 一区的差异化。

## Q3. 能不能做成"多 agent 集群"协作迁移？—— 能，且已有范式，我们在更高层拆分

kernel 级的多 agent 已被验证（CudaForge=Coder+Judge+Nsight；KernelPro=生成-剖析-优化闭环；
VibeCodeHPC 多 agent）。我们把拆分**上移到"算法-管线"级**：
```
Planner   : 读算法源码 + 剖析(torch profiler/Nsight) -> 定位 CPU-bound 热点/可迁移块
Translator: 把热点重写为 GPU (cupy/cuML/torch/自定义 kernel)
Judge     : 跑领域正确性 gate (聚类指标统计等价) —— 领域特色, 通用agent没有
Optimizer : 按硬件反馈迭代加速 (显存/占用/带宽)
Integrator: 缝回原管线, 端到端复测正确性+加速
```
差异化：现有工作在 **kernel 级**编排；我们在 **算法级**编排 + **领域正确性**闭环。用 API
模型（Claude/GPT）就能做 baseline，不需要自训——这对第一篇论文足够。

## Q4. 能不能从零训练自己的迁移 Agent？—— 不建议当第一篇的新意；留给毕业论文

**从零预训练大模型：不可行**（成本天文）。**在开源模型上 SFT/RL 微调出"迁移专用"模型：
可行但这条赛道很挤**——Kevin-32B（QwQ-32B 多轮 RL，correctness 56→82%）、CUDA Agent（大规模
agentic RL）、微调 GPT-5……全是重资源团队在卷**通用 kernel**。

**所以：不要把"我们训了个模型"当卖点，会正面撞车。** 正确顺序：
- **第一篇（承上）**：benchmark + 领域正确性判据 + API-模型多agent baseline + scMAE 案例。
  （必须先有 benchmark 才能造训练数据、才能评测——顺序上也必须先做这个。）
- **毕业论文（启下）**：在这个 benchmark 上，用 **7-8B 开源模型 + LoRA/QLoRA + 真机加速比
  奖励的 RL**（借 "Online RL with Real-Machine Rewards" 2602.12049 的范式）训一个**单细胞
  迁移专用**小模型。新意落在"**领域特化 + 领域正确性奖励**"，不是"又一个通用 kernel 模型"。

## Q5. 代价（时间/算力/钱）多大？

- **第一篇（benchmark + 正确性协议 + API-agent baseline + scMAE GPU 案例）**：
  ~2-3 个月，主要是工程（GPU 重实现 8-12 方法、正确性+加速 harness、agent 编排）。
  算力：我们现有 GPU 1-6 够；API 调用中等花费（agent 迭代）。**风险中、可控。**
- **毕业论文（自训迁移模型）**：额外 6-12 个月。7-8B LoRA 微调可在自有 GPU 完成；
  RL（真机奖励）基础设施复杂、算力更重。**风险较高，但有第一篇的 benchmark 托底。**

## 修正后的框架（保留 scMAE，且不强依赖 agent）

你提到"保留 scMAE 作为迁移案例"——正解。scMAE + DEC + std-floor 是我们**已经吃透机制、
有稳定正确性锚点**的方法，是最理想的**旗舰迁移案例（flagship case study）**：既能展示
"CPU-bound 深度单细胞方法"的迁移全过程，又能用它现成的多数据集结果当正确性基准。

**关键判断：第一篇不必强上 agent。** 两种强度可选——
```
强度A(稳): Benchmark + 领域正确性协议 + 手工/半自动 GPU-native 重实现(scMAE旗舰+若干),
           给出 精度-速度-显存 Pareto + 诊断洞察。 agent 只作"概念验证/future work"。
           -> 投 NeurIPS D&B / ICML benchmark 赛道。最稳。
强度B(高): 在A基础上, API-模型多agent 自动迁移 baseline + 领域正确性gate 闭环,
           agent 成为论文二级贡献。 -> 更像"方法+系统", 上限更高, 工程更重。
```
两者共享同一套 benchmark 与正确性协议，可**先做 A、跑通后加 B**，风险自然分级。
无论 A/B，**毕业论文都接得上**（把 agent/自训模型做成主角）。

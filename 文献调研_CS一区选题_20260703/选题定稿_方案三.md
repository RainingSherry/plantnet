# 选题定稿：方案三（融合）—— 带正确性保证的 GPU 加速单细胞聚类

决定日期：2026-07-03。用户在 强度A benchmark 基础上，选定**方案三**（把已完成的
精度/诊断工作与 GPU 迁移缝成一个故事，让旧工作从"背景"升级为"核心承重"）。

## 一、关键升级：让诊断工作真正承重的那个论点

（不是简单拼接，而是这个论点让两块焊死）

> GPU 迁移几乎总用**近似算法**（近似 KNN / 不同 KMeans 初始化 / 低精度）。
> 我们的诊断已证明细粒度/稀有细胞聚类是**脆弱**的（方差坍缩、稀有亚型先崩、
> KMeans 劈裂主类时聚合 ARI 仍"正常"）。
> ⟹ **聚合 ARI 等价 ≠ 迁移正确**：GPU 近似可能悄悄退化稀有/细粒度结构而聚合指标看不见。
> ⟹ 迁移正确性判据**必须结构感知**（按簇 / 稀有簇 recall / 方差谱 / 边界），
>    而不是只看一个总 ARI——这正是只有具备我们诊断深度的人才能提出的判据。

## 二、三样旧工作全部承重（不再是背景）

1. **正确性判据的"形状"= 结构感知** ← 来自诊断（我们知道脆弱点在哪：稀有亚型、
   方差坍缩、主类劈裂）。这决定协议去查什么、在哪查。
2. **正确性判据的"容差"= 多种子噪声带** ← 来自已测数字（如 Macosko DEC+std-floor
   ARI 0.576±0.087）。定义"GPU 版与 CPU 版统计不可区分"的 band。
3. **旗舰迁移案例 = DEC+std-floor** ← 我们吃透其机制。核心科学问题：
   **方差地板（细粒度聚类的解药）在 GPU 近似算子下还成立吗？** 迁移后 eff-dim
   60→114 的救援是否保留？这是全篇最有说服力、别人做不了的 case study。

## 三、论文骨架（承上）

标题方向：《Correctness-Preserving GPU Acceleration of Single-Cell Clustering》

核心贡献：
1. **Benchmark**：方法动物园(CPU 参考实现) × GPU 迁移 × 规模阶梯(10k→1M)，
   三轴 = 正确性 × 加速比 × 显存。
2. **结构感知统计等价正确性协议（智力脊梁）**：非 bit-match、非单一聚合 ARI；
   确定性子步 allclose(rtol)；随机端到端在**多种子噪声带内**做 TOST 等价，且**按簇/
   稀有簇/方差谱**分层校验。区别于 KernelBench(bit-match) 与 Correctness-Illusion/
   ProofWright(数值/形式化级)——**随机领域算法的结构感知迁移正确性是新问题**。
3. **诊断驱动的加速优先级**：用已有诊断洞察决定"哪些机制值得加速"（精度赢家如
   DEC+std-floor）、"哪些 GPU 近似是安全的"。
4. **旗舰案例**：DEC+std-floor 的方差地板机制在 cuML/近似算子下的存活性。
5. Phase 1 已量化的"缝"：朴素 `.to(cuda)`≈0 收益、经典步骤 CPU 超线性不可行、
   cuML 7–33× 且规模越大越值 —— 作为 motivating evidence。

## 四、毕业论文（启下）

在本 benchmark 上做**单细胞算法 GPU 迁移 Agent**：多 agent(Planner/Translator/Judge/
Optimizer/Integrator) + 硬件反馈 + **结构感知正确性 gate 作为奖励/约束**。Judge 用的正是
本论文的正确性协议——这是领域特色，通用 kernel agent 没有。

# 植物单细胞数据与稀疏矩阵方法迁移预研综述

## 检索范围与判断准则

本报告按“系统综述 + 方法迁移预研”组织，核心目标不是重复植物单细胞研究已经得到的生物学发现，而是把可复用的**计算流程**、**矩阵处理方式**与**稀疏性应对策略**尽可能抽离出来，转译成一个适合方法迁移与算法设计的工程框架。检索优先使用论文原文页、GEO/SRA/ENA/EMBL-EBI Single Cell Expression Atlas（SCEA）数据页、数据库官网与官方代码仓库。数据纳入范围覆盖植物 scRNA-seq / snRNA-seq，必要时延展到动物/人类单细胞方法学文献，用于建立强基线（strong baselines）与迁移候选模型。citeturn37view0turn37view2turn33view0turn49search0

从资源层面看，植物单细胞数据已经不再是“少量散点式数据”，而是开始形成可做方法学研究的中等规模生态。scPlantDB 在 2024 年整合了 67 个高质量数据集、17 个物种、约 254.7 万个细胞，并对细胞类型与 marker 进行了统一整理；Plant Cell Marker DataBase（PCMDB）则手工整理了 81,117 个 marker，覆盖 6 个植物物种、263 个细胞类型与 22 个组织。SCEA 的单实验下载页已经把“实验元数据—raw counts—normalized counts—聚类文件—marker gene 文件”作为标准化下载构件，意味着对于算法研究者来说，植物领域已经具备了比早期更适合做重现实验和横向比较的数据基础。citeturn37view0turn37view2turn33view0

在分析流程上，2024 年《The Plant Cell》的最佳实践评述已经把植物 sc/snRNA-seq 的主流程明确概括为：**read mapping（读段比对）→ read counting（读段计数）→ QC and cell selection（质控与细胞筛选）→ normalization（归一化）→ dimension reduction（降维）→ cell clustering（细胞聚类）→ doublet identification（双细胞识别）→ DEG analysis（差异基因分析）→ sample integration（样本整合）→ cluster annotation（细胞群注释）→ validation / data mining（验证与下游挖掘）**。这条流程线并不只是“建议”，而是对现有植物论文共同结构的高度抽象。对于稀疏矩阵算法迁移来说，这一点很关键，因为它说明你要替换或增强的模块，主要落在 **normalization / feature selection / latent representation / graph construction / integration / annotation transfer** 几个位置，而不是整个流程重写。citeturn36view1turn35view4turn35view6

还有一个对方法迁移非常重要的观察：植物论文近两年越来越重视的，往往不是“零膨胀（zero inflation）”本身，而是**环境 RNA（ambient RNA）污染、双细胞、细胞/细胞核输入方式差异、叶绿体/线粒体 reads、snRNA 的 intronic reads、以及物种/组织/处理条件引起的批次偏移**。2026 年的一篇植物方法学工作在玉米上明确把 SoupX、CellBender、DoubletFinder、Harmony 与 Seurat v5 串成了一个可核验的工程流水线，这对你做稀疏算法迁移很有启发：植物场景中的“噪声”并不等同于抽象的数学稀疏，而是混合了生物技术偏差、组织解离偏差与测序噪声的复合稀疏。citeturn50view0turn50view2turn50view4

## 数据资源版图与可复用性结论

从数据库生态判断，植物领域已经具备做“算法迁移验证”的三个必要条件。其一是**跨物种覆盖**：Arabidopsis、rice、maize 已经形成多组织、多阶段、多处理条件的数据堆叠，wheat、soybean、cotton、tomato 等作物的公开数据也开始达到可做任务级 benchmark 的程度。其二是**元数据可追溯性增强**：SCEA 直接提供 raw counts、normalized counts、clustering file 和 marker gene files；GEO 中越来越多研究开始同时上传 MTX/H5、Seurat object / RDS、系列矩阵与样本说明。其三是**细胞类型知识库开始成形**：scPlantDB、PCMDB、以及用户请求中特别提到的 PlantscRNAdb 一类资源，使植物单细胞注释不再完全依赖人工 marker 回忆，而是开始进入“数据库 + 参考映射 + 交叉物种转移”的阶段。citeturn37view0turn37view2turn33view0turn0search23

对方法研究者而言，这意味着植物数据不再只是“拿一两个阿拉伯芥根尖图谱做可视化”的状态，而是可以把任务拆成更清楚的计算模块。你可以把数据集按四类组织：**发育谱系型 atlas**，例如根、花、茎尖、叶原基；**处理响应型 atlas**，例如盐胁迫、病原侵染；**跨样本/跨基因型整合型 atlas**，例如 WT/突变体，或鲜活细胞/新鲜细胞核/冻存细胞核比较；**多模态/空间联动型 atlas**，例如 scRNA-seq + scATAC-seq，或 snRNA-seq + spatial transcriptomics。这些类别对应的算法切入点完全不同：前两类更适合做表示学习与轨迹稳定性，第三类更适合做批次校正与领域自适应，第四类更适合做图模型、多视图学习与半监督注释。citeturn49search0turn55view0turn15view2turn47search0

同样需要强调的是，植物单细胞并不等于单一技术。当前公共资源中同时存在 **protoplast-based scRNA-seq（原生质体单细胞 RNA 测序）** 与 **snRNA-seq（单核 RNA 测序）**。2026 年玉米方法比较表明，原生质体输入通常具有更好的转录本完整性与更高的 feature 检出，细胞核输入对难解离组织更稳健，但特征数更低、背景 RNA 与不确定簇更多。对于稀疏矩阵算法迁移，这意味着不能把“稀疏”视为单一统计现象，而应把输入类型作为显式协变量纳入模型。citeturn49search0turn50view0turn50view4turn50view5

## 稀疏性处理方式与矩阵工程模式

围绕你最关心的“稀疏性处理”，现有植物论文大致呈现出一种**弱显式建模、强工程折中**的格局。所谓“弱显式建模”，是指大多数植物论文并不会在方法部分正面讨论“零值究竟是真无表达（true zero）还是 dropout / capture failure”，也很少把零膨胀当成分析主轴。所谓“强工程折中”，是指研究者通常通过**细胞筛选、基因筛选、HVG 截断、图邻域平滑、伪时序子集分析、marker 驱动注释**来间接处理稀疏性。2024 年植物最佳实践文献把环境 RNA、空液滴、双细胞、线粒体 / 叶绿体 reads、以及 intronic reads 的报告列为关键元数据项，而没有把“是否采用 zero-inflated model”列为统一核心要求，这恰恰反映了植物领域对稀疏问题的现实判断：在许多植物 sc/snRNA 任务里，**技术噪声与样本制备偏差往往比纯统计式零膨胀更先成为瓶颈**。citeturn35view0turn35view3turn35view4turn36view1

把论文逐篇对照后，这种判断会更清楚。Rice root 的 Nat Commun 论文是少数显式写出插补步骤的植物工作：作者先用 Seurat 进行 QC、LogNormalize、HVG、PCA、Louvain、UMAP/t-SNE，再在 Palantir 伪时序中使用 diffusion maps 与 MAGIC 插补，并在另一条支路上用 Scanpy 做 ComBat、diffmap 和 ForceAtlas2；也就是说，插补并不是前置的“统一去噪层”，而是服务于轨迹重建和动态表达趋势建模的局部工具。与之相比，2026 年植物方法学 benchmark 更强调的是 SoupX、CellBender、DoubletFinder 与 Harmony，说明植物领域对稀疏矩阵的“先验修正”越来越偏向**背景污染去除、质量控制与批次对齐**，而不是普遍性的矩阵补全。citeturn55view0turn55view3turn50view0turn50view2

从矩阵工程角度出发，可以把现有植物单细胞工作流概括为四类常见操作。第一类是**删除型稀疏处理**，即通过 cell / gene filtering 与 HVG 选择，把极端稀疏、信息量低或无法稳定估计的部分提前扔掉；这是 Seurat / Scanpy 风格流程的主导策略，也是你未来做方法迁移时必须对照的最强传统基线。第二类是**图约束型稀疏处理**，即通过 kNN / SNN 图，把高维稀疏计数转化为局部邻域结构后再进行 Louvain / Leiden 聚类或 UMAP 可视化；这类方法实际上把“稀疏矩阵问题”转译成了“局部几何结构问题”。第三类是**轨迹 / 扩散型平滑**，典型代表就是 Palantir + diffusion maps + MAGIC，它们在连续分化任务中通过局部扩散把 dropout 噪声平滑掉，但这也会引入过平滑风险。第四类是**显式概率模型或自编码器**，在植物原始论文里还不是主流，但在通用单细胞方法中已经非常成熟，例如 scVI、DCA、scDeepCluster、scDCC、scGNN；恰恰是这一类，最值得与你的非生物稀疏矩阵算法发生方法学对接。citeturn36view1turn55view0turn57search0turn57search2turn57search3turn58search4

还有一个容易被忽视、但对植物尤其关键的点：**scRNA-seq 与 snRNA-seq 的稀疏性不是同一种稀疏性**。2026 年玉米比较研究显示，细胞核数据通常检出的 feature 更少，背景污染更高，而且会出现更多“无法清晰归属”的混合簇或不确定簇；这意味着如果你把一个在通用稀疏矩阵上表现很好的降维 / 聚类算法直接平移到植物 snRNA 矩阵上，而不把“核转录组低特征、3' 偏倚、intronic signal、ambient RNA”作为建模对象，它很可能只是在学习制样方式，而不是学习真实细胞状态。对于植物方法迁移，最稳妥的范式不是把“稀疏”抽象成一个统一 Bernoulli 缺失过程，而是至少要把**输入类型、组织来源、物种、处理条件、器官细胞器 reads 比例**作为显式协变量或正则项。citeturn49search0turn50view0turn50view4turn50view5

## 结论与预研建议

如果把这些证据压缩成一句判断，那么结论是：**植物单细胞领域目前最缺的，不是数据，而是能够在 raw sparse counts 上同时兼顾批次鲁棒性、轨迹稳定性与解释性的表示学习方法**。现有植物论文已经积累出足够广的 atlas 资源，也形成了较统一的 Seurat / Scanpy 流程基线；但真正显式面向稀疏矩阵本体的创新，还大多停留在通用单细胞方法学，而未充分渗透到植物主流分析实践中。换句话说，你的研究方向并非“重复造轮子”，而是恰好落在一个**资源已成熟、问题仍未解决、跨领域迁移价值很高**的窗口期。citeturn37view0turn36view1turn50view0turn58search4turn57search0

就具体预研路线而言，我更建议把算法迁移分成三层，而不是一次性追求“端到端全胜”。最底层是**工程兼容层**：算法必须直接接受 MTX / H5 / AnnData / Seurat object 中的 raw counts，并能显式处理 snRNA 的低 feature、intronic read、ambient RNA 与 organelle read covariates；如果模型一上来就要求对矩阵做全量 densify（稠密化），那么它在植物大 atlas 上通常会首先输给工程现实。中间层是**任务对照层**：至少要与 Seurat / Scanpy-PCA、Harmony、scVI、DCA、scDeepCluster 这些基线做并排比较，因为它们分别代表了图聚类标准流、低维批次对齐、概率生成模型、深度去噪与联合聚类。顶层才是**解释性层**：真正有发表潜力的植物方法学工作，最好不仅能给出更漂亮的 UMAP，还能解释“这个低维坐标轴为什么对应某个组织层、某个发育方向、某个盐胁迫状态或某个跨物种保守 marker 模块”。citeturn56search1turn56search12turn58search1turn56search2turn57search0turn57search1

若从你自己的“非生物方向稀疏矩阵算法”出发，我认为最值得优先试验的迁移接口有三种。其一是**稀疏低秩表示 + count-aware reconstruction**：也就是不要只在 log-normalized dense embeddings 上做线性代数，而是在 raw count 或轻度标准化后的稀疏矩阵上保留计数性质，让低秩结构与 NB / Poisson 类似然发生耦合。其二是**图正则化的稀疏编码**：把 kNN / SNN graph 当作结构先验，而不是把邻接图构建留给 PCA 之后，这对植物连续谱系和局部过渡状态尤其重要。其三是**marker / orthology aware semi-supervision**：利用 wheat root atlas 这类跨物种注释转移工作，把 PCMDB / scPlantDB / 植物已有 marker、同源映射与少量人工标签转成约束项或对比学习正样本。这样做的意义在于，植物数据经常不是“标签全缺失”，而是“标签少而珍贵”。citeturn15view2turn44search0turn37view0turn37view2turn57search2turn58search4

还需要一个现实判断。植物领域的“最佳新方法”未必是最复杂的 foundation model，而更可能是一个**保持稀疏、兼容原始 count、能吸收植物先验、能够无缝接入 Seurat / Scanpy 下游接口**的中尺度模型。原因很简单：植物研究者极度依赖 marker、in situ、组织学验证与跨论文复核。如果一个模型把表示做得很强，却无法告诉使用者“哪一组基因、哪一条谱系、哪一种组织层差异在驱动聚类”，它在植物领域的接受度通常会低于在人类 PBMC 数据上的接受度。因此，从发表策略看，**解释性稀疏表示学习（interpretable sparse representation learning）** 比黑箱式超深模型更可能迅速进入植物分析实践。citeturn36view1turn35view4turn47search0turn15view2

尚需说明的限制也很清楚。本次检索中，部分论文公开 HTML 页没有展开完整补充方法，因此少数研究只能核验到“流程级”而非“参数级”；个别最近数据集属于 2025–2026 年的新论文或预印本，代码和处理矩阵虽已公开，但 citation 生态与社区复用尚在形成中；此外，用户点名的部分数据库如 PlantscRNAdb 已能确认其扩容事实，但某些单条数据集的细粒度仓库字段，在本轮检索中未能全部逐条展开。尽管如此，就“植物单细胞数据是否足够支撑稀疏矩阵算法迁移研究”这一核心问题而言，答案已经非常明确：**足够，而且现在正处在从生物问题驱动走向方法问题驱动的转折期**。citeturn0search23turn37view0turn49search0
